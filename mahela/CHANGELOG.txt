MahELA Prototype — Changelog
==============================

v1.7.0 — Current
------------------
- Admin > Teachers: added a "View Teacher's Students" action (people
  icon on each teacher row) that opens a modal listing that teacher's
  students, with the same View Profile and Reset Password actions
  available inline -- so an admin can manage any teacher's roster
  without leaving the Teachers page. Reset Password is now shared
  between the teacher- and student-reset flows, with the right title
  and confirmation toast for whichever one you're resetting.
- Fixed the clock/date widget rendering as a broken, stacked layout
  on every authenticated page except the landing page: .hide-mobile
  carried a base "display: initial" rule that -- at equal CSS
  specificity, later in the stylesheet -- silently overrode
  .clock-widget's (and .btn's) own "display: flex/inline-flex" above
  780px. Removed the pointless base rule; hiding below 780px is the
  only job this utility ever needed, and that part was already scoped
  to a media query. The clock widget (and the "Back to Dashboard"
  button that shared the same class) now render identically
  everywhere.
- Calendar: schedule dates ("Next class", session rows, "Student
  since", settlement periods, skill-assessment history) now actually
  switch to Shamsi when you switch the UI to Persian -- previously
  only the clock widget's own date did this; everything else was
  static text. Also added a Calendar section to Settings so anyone
  can choose Gregorian or Jalali independent of their language
  (e.g. Persian UI with Gregorian dates, or English UI with Jalali),
  saved and changeable any time. Every date on screen re-renders
  immediately when either the language or the calendar preference
  changes.
- Teacher panel > Messages: the sidebar link went nowhere before.
  Added messages.html, a real inbox with a conversation list (one per
  student, showing the last message and time) and a full message
  thread on the right, deep-linkable via ?student=<key>. Composing a
  message now has a small formatting toolbar (bold, italic) and an
  emoji picker, shared with student-detail.html's per-student
  Messages tab so both surfaces work the same way.
- Fixed several more spots that were still using white text on the
  mid-tone brand colors, missed in the v1.6.0 contrast pass because
  they were inline styles rather than the shared stylesheet: sidebar
  and message-bubble avatars, the profile header avatar, and the
  teacher-strip avatar on the student panel.
- Fixed a dark-mode-only contrast regression introduced in the
  v1.6.0 fix itself: several rules switched avatar/button/bubble text
  from white to var(--ink) to fix light-mode contrast, but --ink
  flips to near-white in dark mode ([data-theme="dark"] --ink:
  #F3F0FB) while the backgrounds they sit on (--brand, --c-pink,
  --c-teal, --student-accent) don't change -- so those same elements
  went right back to a ~2.5:1 failure, just now only in dark mode.
  Switched all of them to the theme-stable --c-ink instead (same fix
  already used for the toast background in v1.6.0).
- Fixed the emoji picker rendering open by default on page load: its
  class set "display: grid" unconditionally, which -- as an author
  stylesheet rule -- overrides the browser's own "[hidden] {
  display: none }" UA rule. Added an explicit
  ".chat-composer__emoji-popover[hidden] { display: none; }" rule.
- Fixed modal Escape/focus behavior for two modals open at once (e.g.
  Reset Password opened from inside the Teacher's Students modal):
  the v1.5.0 keyboard handling picked the "topmost" modal by DOM
  order, not open order, so Escape could close the wrong one and
  focus could return to the wrong trigger. Modals now track an
  explicit open-order stack.
- Added data-i18n-aria (translates aria-label + title together) and
  extended data-i18n-ph to also update a contenteditable composer's
  CSS-based placeholder, not just the native placeholder attribute --
  both needed for the new Messages toolbar/composer, both reusable
  for future icon buttons and rich-text fields.

v1.6.0
------------------
- WCAG AA contrast fixes across every button, active nav link, chat
  bubble, avatar, and the finance highlight card: white text/icons on
  the mid-tone brand colors (pink, teal, orange, green) failed
  contrast (1.9-3.3:1); switched all of them to the existing --ink
  token, which clears 5.5-9.5:1 against every one of those colors
  with no new colors introduced. Also fixed the toast component,
  which used the theme-flipping --ink token for its background and
  went invisible (near-white on near-white) in dark mode specifically
  -- it now uses the theme-stable --c-ink. Darkened/lightened
  --ink-faint (both themes) from 2.8-3.9:1 to 4.6-5.2:1.
- Accessibility: every form field's <label> is now programmatically
  associated with its input via id/for (was 0 of 49 app-wide -- every
  field previously had no accessible name at all). All 8 modals
  across 5 pages now get role="dialog", aria-modal, aria-labelledby,
  focus-on-open, Escape-to-close, a Tab focus trap, and focus-restore
  on close automatically from shared app.js wiring. All 3 tab groups
  (login role tabs, student-detail, student-panel) now implement the
  full WAI-ARIA Tabs pattern with Left/Right/Home/End keyboard
  navigation, mirrored correctly for RTL. Toast notifications are now
  announced via role="status" aria-live="polite". Icon-only table
  actions (view profile, reset password, permissions, suspend) gained
  aria-label alongside their existing title. Decorative required-
  field asterisks are now aria-hidden.
- RTL: the "Back to Dashboard" / "Back to login" arrow icons pointed
  the wrong direction in Persian (fixed with a new, reusable
  .icon-flip-rtl class); the account Settings page's gender dropdown
  used the same "دختر/پسر" (girl/boy) labels as student records --
  split out adult-appropriate "زن/مرد" (woman/man) labels for
  settings.html specifically. Audited the rest of the RTL experience
  (logical CSS properties, table/sidebar mirroring, icon
  repositioning, tab/checkbox order) and found it was already
  correctly built -- no further changes needed there.
- Added design-system/MASTER.md: the design-token reference, contrast
  rule, component patterns (buttons/forms/modals/tabs/toasts), i18n
  conventions, and an accessibility checklist for building any new
  screen consistently with what's already shipped.
- Added docs/wordpress-migration.md: roles/capabilities, CPT + meta
  schema (teacher_id as the row-level security boundary), a REST
  route table for every currently-mocked form action, concrete
  CAPTCHA/password-reset implementation notes, and a phased rollout
  order for the eventual WordPress build.

v1.5.0
------------------
- Added a full Admin Panel (3 new pages) with its own login tab:
    - admin-dashboard.html: system-wide KPIs (total teachers, total
      students, sessions this month, revenue this month) and quick
      links.
    - admin-teachers.html: every teacher account, with a "+ Create
      Teacher" flow, a per-teacher Permissions panel (toggle switches
      for Manage Students / Schedule / Finance / Skill Assessments /
      Messages -- this is the "reduce a teacher's access" feature),
      a password-reset action, and Suspend/Reactivate.
    - admin-students.html: every student across every teacher --  the
      one view a regular teacher never gets, since teachers only ever
      see their own roster.
  A teacher's Active/Restricted status badge now derives automatically
  from whichever permissions are actually turned on for them.
- Login page now has a third "Admin" tab alongside Teacher/Student.
- Added a CAPTCHA-after-failed-attempts flow to all three login tabs:
  3 simulated failed attempts trigger a simple math challenge that
  must be solved before the next attempt can proceed (traced the exact
  state machine in Node to confirm the logic before shipping it --
  wrong answers correctly regenerate the challenge and block
  progress; a correct answer lets the next submit through). Real bot
  protection still needs a server-side CAPTCHA service and backend
  attempt-tracking; this is the client-side UX layer only.
- Added forgot-password.html: enter your email, get a (mocked, since
  no backend can send real email yet) confirmation that a reset link
  was sent -- using security-conscious wording that doesn't reveal
  whether the email exists in the system.
- Every account-creation and profile form (Add Student, Create
  Teacher, Settings) now requires a valid email AND a valid mobile
  number, with a shared client-side validation layer
  (window.mahtelaValidate) that shows inline errors on blur.
- Settings page now has a third Admin variant (settings.html?role=admin)
  and a mobile number field alongside email, consistent with the new
  validation requirement.

v1.4.0
--------
- Found and fixed the real bug behind the invisible-but-clickable boxes
  (confirmed from your DevTools screenshot -- the DOM content was
  genuinely all there, "Elena Kim" and all, it just never became
  visible). The cause: the fade-in animation CSS required the
  .reveal-group element ITSELF to carry the .is-ready class
  (.is-ready.reveal-group .reveal-item, no space = same element), but
  the JS only ever added .is-ready to <body>. Every .reveal-group
  section on the dashboard (stats row, student cards) was stuck at
  opacity:0 forever as a result -- present, clickable, invisible.
  Fixed to a plain descendant selector so it matches correctly.
- Removed signup entirely, matching the real account model: an admin
  creates teacher accounts, and teachers create student accounts --
  there's no public self-registration for anyone. The login page's
  teacher tab now points to a short note instead of a signup link.
- Added a real Settings/Profile page (the sidebar link went nowhere
  before): profile photo upload with live preview, editable name/email,
  a gender selector, and a separate password-change form with mismatch
  validation. Works for both teacher and student accounts
  (?role=teacher / ?role=student) from the same file.

v1.3.0
--------
- Fixed the real cause of "Gregorian dates still there in Persian mode":
  I had made both dates show with Persian digits, but the Gregorian one
  was still fundamentally a Gregorian-calendar date (just spelled out in
  Persian) -- which reads as foreign to a Persian UI. Persian mode now
  shows ONLY the Shamsi date (and its separator), matching how an
  Iranian audience actually expects a Persian-language interface to
  behave. English mode still shows both calendars side by side.
- Centered the clock/date text in the widget, in both languages.
- Every amount now has 3-digit grouping, including the price input
  fields in "Add Student" and "Edit Details" (previously plain number
  inputs, which browsers never format) -- they now live-format with
  comma separators as you type, the same technique used in the earlier
  rahn/ejare calculator project.
- Fixed the real bug behind "clicking Students shows nothing, but the
  links under Add Student go to a default student": every student card
  linked to the exact same static page, which only ever displayed
  Elena's hardcoded data no matter who you clicked. Student cards now
  carry a ?student=<key> link, and student-detail.html reads it to
  render the correct name, avatar, gender, level, rate, and skills for
  whichever student was actually clicked (falls back to Elena if the
  key is missing or invalid). The "Edit Details" modal now also
  pre-fills with that same student's real data instead of always
  showing Elena's.
- Removed the redundant "Students" sidebar item, which pointed to the
  exact same page as "Dashboard" and so appeared to do nothing when
  clicked.

v1.2.0
--------
- Fixed: switching to Persian now fully localizes the clock widget --
  both the Gregorian and Jalali dates convert to Persian digits and
  Persian month names, not just the Jalali one.
- Fixed: chat bubble direction in the Messages tab now correctly
  mirrors under RTL. This turned out to be a genuinely ambiguous corner
  of CSS (flex-direction:row-reverse interacting with direction:rtl),
  so it's rebuilt on a more robust foundation: bubble side comes from
  margin-inline auto-positioning (unambiguously direction-aware) and
  the avatar's position comes from literal DOM order for outgoing
  messages, rather than relying on row-reverse.
- Added a real settlement checklist to the Finance tab: every
  unsettled session now has its own checkbox, plus a "Select All"
  toggle, so a teacher can settle e.g. 5 out of 10 classes instead of
  only ever settling everything at once. The selected count and total
  update live as boxes are checked, in whichever language/currency
  format is active.
- Fixed a small pre-existing inconsistency: Elena's own chat avatar
  (in her own panel) was hardcoded teal even though she's set as
  female (pink); now follows the same gender-accent variable as the
  rest of her profile.
